# ClearYield: project context

Personal, self-hosted investing dashboard. The goal is a smart decision-support tool for the owner's own investing: prices, charts, transparent scores, recommendations and portfolio analytics. It is **not** a signal-selling or trading bot. It never places trades: it prepares orders from the owner's targets, the owner approves them and places them at their broker (`orders.py`).

## Owner's choices (keep these unless told otherwise)
- **Delivery:** local full-stack app on a Windows PC (run from VS Code / PowerShell), on **port 8001** (8000 belongs to another app).
- **Investing style:** balanced mix. Factor weights default to 20% each across value, quality, growth, momentum and risk. Core and satellite, with an 80% core target by default.
- **Markets:** the whole world, in five regions: North America (US, Canada), Europe, Latin America (Brazil, Mexico, Chile, and New York listings for Argentina, Peru, Colombia, Uruguay), Middle East & Africa (Qatar `.QA`, Saudi `.SR`, Dubai `.AE`, Kuwait `.KW`, Israel `.TA`, Turkey `.IS`, South Africa `.JO`) and Asia-Pacific (Japan, Hong Kong, India, Korea, Taiwan, Australia, Singapore, Indonesia), plus ETFs and crypto (`-USD`). 407 stocks, every one checked on Yahoo (a year of prices, a sector, its exchange's currency). Settings' "Regions you follow" (`regions`, all five by default) decides which are downloaded, screened, scored for Opportunities and ranked against; Research opens any symbol. Within a region, a country filter (and the Gulf as a group) narrows the Screener; the owner's interest in the Gulf is served that way.
- **Recommendations:** always explained, never a bare "BUY". Every score must stay traceable to named metrics and thresholds.

## Run
```powershell
.\run.bat                     # creates .venv on first run; live Yahoo data on http://localhost:8001
.\run.bat --demo              # synthetic offline data
.\run.bat --restart           # stops a copy already running (e.g. the background one), then starts this code
.\.venv\Scripts\python tests\test_smoke.py      # offline end-to-end tests (demo mode); add a name part to run some, -v for the app's log
.\.venv\Scripts\python tests\run_all.py         # everything: offline tests, browser checks, demo and live walks, raw-Yahoo comparison
.\.venv\Scripts\python tests\run_all.py --offline   # skip the live parts
.\.venv\Scripts\python tests\run_all.py --only walk-live
```
- The browser checks need `npm install` once in `tests/browser`, and use the installed Chrome (`channel: "chrome"`).
- `run_all.py` gives each browser check its own server and temporary database, so the owner's data isn't touched. It leaves out the app's log lines, ends with each failing step by name, and on a failure prints the end of that check's output and its server's log.
- `requirements.txt` pins the versions the tests last passed with (certifi only has a floor). `run.bat` installs again whenever `requirements.txt` changes (it keeps a copy in `.venv\requirements.installed`). Upgrade on purpose, then run `run_all.py`.
- `uvicorn --reload` has not reliably picked up Python changes on this machine. Restart the server after backend edits (`run.bat --restart`).
- **Start with Windows** (Settings, applies at once): `startup.py` puts `ClearYield.lnk` in the Startup folder, running `pythonw -m backend.background` (no window; output to `data/server.log`, kept to 5 MB plus one older file; exits if the port already answers). `run.bat` just opens the page when a copy already answers; `--restart` sends `POST /api/stop` and waits for the port to free. Tests point `CLEARYIELD_STARTUP_DIR` at a temporary folder, never the real one.

Optional settings go in `.env` (see `.env.example`):
- `AI_PROVIDER` (`anthropic` | `openai_compatible` | `none`), `AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY`, `AI_TIMEOUT`, `AI_THINKING` choose the model for briefs and screener questions. `.env.example` has a block for Ollama, LM Studio, OpenRouter, Groq and Anthropic. A `.env` with only `ANTHROPIC_API_KEY` (and `ANTHROPIC_MODEL`) still turns on Anthropic.
- The owner's `.env` uses Groq (`openai/gpt-oss-120b`, `AI_THINKING=on`), with Ollama (`gemma4:e4b`, `AI_THINKING=off`) kept commented out. `AI_THINKING`: `off` sends `reasoning_effort: "none"` (on Ollama's `/v1/chat/completions` it's the only switch that works; `think: false` is ignored), `on` gives six times the reply allowance, `low`/`medium`/`high` set the effort. A thinking model given a normal allowance can spend it all reasoning and return nothing: gemma4 with thinking on did that for 7 of 7 briefs. A key left as `my_api_key` counts as not set up. `AI_API_KEY` may list several keys, comma-separated: on a rate limit (or Groq's "blocked at the organization level", which it sent with the day's allowance used up) `ai.switch_key()` rests that key in the cache, by fingerprint, for as long as the provider said, and the call carries on with the next (`agent._post` and `ai.complete`); with every key resting the day's limit is reported "on every key".
- `TAVILY_API_KEY` (free plan, 1,000 searches a month) gives Ask web search with links; without it, a gpt-oss model on Groq uses Groq's browser search. `WEB_SEARCH=off` turns it off.
- `ALERT_CHECK_MINUTES` sets how often alerts are checked.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SECURITY` set the mail server for alert emails (`mailer.py`); the password stays in `.env`, never in the database or a backup. The tests set `SMTP_HOST=""` so they never email the owner.
- `CLEARYIELD_DB` moves the database; `CLEARYIELD_DEMO=1` switches to synthetic data.

## Stack
- **Backend:** Python, FastAPI, yfinance, pandas/numpy, SQLite. No ORM; raw SQL lives in `db.py`.
- **Frontend:** a single page with no build step: `index.html`, `app.js` and `styles.css` in vanilla JS. Libraries are bundled in `frontend/vendor/` (no CDN):
  - Lightweight Charts v4.2, for the price, RSI and MACD charts. Its logo is hidden (`attributionLogo: false`) and TradingView is credited in the README, as its licence asks.
  - Chart.js v4.4, for everything else
  - marked and DOMPurify, for rendering the brief's markdown safely
- FastAPI serves the frontend at `/` and `/static`, and the favicon at `/favicon.ico`.

## Backend map (`backend/`)
| File | Role |
|---|---|
| `main.py` | All REST routes. Loads `.env`. Runs the background alert loop. Every response goes through `ok()`, which makes NaN/inf/numpy values JSON-safe. Dashboard tiles: `_tiles()` is the catalogue (`MACRO` plus the owner's custom tiles); `/api/tiles` adds a custom tile only after Yahoo returns at least two days of history, and `DELETE /api/tiles/{t}` removes one. `/api/buckets` sets a holding's core/satellite bucket. |
| `data.py` | Yahoo access with SQLite caching, demo mode and FX. `ownership()` (`own:v1:`, a day; nothing found an hour) gives insiders' and institutions' shares, the largest institutions and funds with their latest change, and the past year's insider trades, each classed by `insider_kind()` from Yahoo's description: only "Purchase at price" / "Acquisition in the public market" is a buy and "Sale at price" / "Disposition in the public market" a sale; awards, exercises, gifts, conversions and buy-backs are `other` (Yahoo's own summary counts awards as purchases: Apple's 11 "purchases" were all awards). Checked against Yahoo's six-month tallies (JPM 8 sales of 37,834 shares, both). Mostly US and Canadian companies have records. A watch on the log (`_RateLimitWatch`) notices Yahoo's "Too Many Requests" and `rate_limited_for()` pauses long batches (`insights.rows_for` in batches of 40, `patience` seconds; the background waits up to 15 minutes). `history()` fetches 5y of daily prices once and slices shorter periods from it. `intraday()` gives 5m/15m candles for the 1D/5D charts; `weekly()` builds weekly candles from daily ones. `search_symbols()` is Yahoo's own symbol search (24h cache). `/api/search` puts an "Ask the Screener" row (`screen: true`) first when the keyword rules (`ai._parse_rules`) read every word ("CHEAP", "banks"), after the stocks when some words weren't read; the page re-searches on Enter if the results shown were for shorter text. `fx_rate()`/`fx_series()` route crosses through USD and handle minor units (GBp, KWF) and pegs. Cache keys carry a version (`info:v8:`); bump it when stored fields or derived values like the region change. |
| `ledger.py` | The transaction ledger: buys, sales and dividends replayed first in, first out; XIRR. |
| `portfolio.py` | Positions from the ledger, base-currency conversion at each date's FX, allocation (incl. fund look-through), risk, warnings, rebalancing, fund costs (`_fund_costs`: each fund's yearly cost on what's held, as a share of the portfolio and of the funds; `_cost_of` takes your figure from Settings' `fund_costs` over Yahoo's `netExpenseRatio`, which European funds like VWCE.DE lack; a fund with neither is named, never guessed; prices already have the cost taken out, so simulations don't subtract it again), and core/satellite: the split against target, each bucket's share of variance (`_risk_shares`, sums to 1), and each bucket's time-weighted return over the days both were held (`_bucket_performance`). |
| `indicators.py` | SMA/EMA/RSI/MACD/Bollinger, plus returns, volatility, drawdown, CAGR, Sharpe, Sortino and beta. Windows are measured in calendar time (`window()`), not row counts. |
| `scoring.py` | Five factors scored 0-100 via `lin(x, bad, good)` thresholds; each factor is the average of its available metrics. Growth uses 3-year yearly growth of revenue and net income from the annual statements (`insights.multi_year_growth()`, passed in by `evaluate_ticker()`), falling back to the latest quarter's YoY, labelled so. Risk is on one scale for every asset (no looser crypto scale). For banks, margins, debt/equity and the current ratio are listed but not scored (`BANK_NOTE`), so quality rests on ROE; metrics with a `note` don't count against data coverage. The composite is a weighted average over factors that have data (ETFs and crypto get only momentum and risk). Stance bands: ≥70 Strong, ≥58 Favorable, ≥45 Neutral, ≥35 Caution, else Weak. |
| `insights.py` | Ownership: `insider_summary()` counts insiders' market buys and sales over `INSIDER_MONTHS` (6) from `data.ownership()`, with a plain sentence (selling is called common and often routine; awards are never buying). Sector ranks: `peer_table()` keeps every listed stock's sector and factor scores (seven hours; the overall score is worked out with the current weights via `scoring.combine`, so changing weights doesn't rescore), and `sector_ranks()` gives, per score, the share of the other stocks in its sector, from every market, that it beats (a tie counts half), how many, and their middle; fewer than `MIN_PEERS` (8) others, no rank. Stocks outside the list are ranked against it. The Screener's rows carry `sectorBeats`/`sectorOf`. Screener (threaded; besides the ratios it filters market cap in dollars (`marketCapUsd`, Yahoo's figure in the main unit at today's rate), price to book, RSI, past-year and year-to-date returns, distance from the 52-week high and low, factor-score minimums, industries (Yahoo's names, or part of one such as "Banks") and "beat the market" (past-year return above `BENCHMARK`, ACWI, noted with its return); a region asked for but not followed is left out with a note, never swapped for the followed ones), compare with weekly-return correlation, DCF, alert checks, the daily digest and score history. The digest is rule-based (no AI): alerts and journal reminders, then `portfolio_points()` (latest-day change, core share against target, the Portfolio page's warnings), holding/watchlist moves and events, `market_moves()` over the shown tiles with limits per kind in `MOVE_LIMITS` (yields in percentage points, from the same calendar month as the tiles), and `recent_headlines()` (stocks and coins you hold or watch, past 3 days, http(s) links only; funds left out, their feed being general news; when none of yours has any, up to `MARKET_NEWS_COUNT` market headlines from `MARKET_NEWS` (^GSPC) take their place, marked `market`, so someone holding only funds still gets news). The page lists the rules in `DIGEST_RULES`; keep it in step. It shows two tabs, Highlights and News (headlines), remembered in localStorage. A market line's colour says good or bad: a rising VIX is red, yields and currencies are neutral. |
| `tax.py` | A calendar year from the ledger (`GET /api/tax?year=`, `GET /api/tax.csv?year=`): each sale piece first in, first out, cost and proceeds each at its own date's rate in the base currency (`portfolio._lot_fx`/`_sale_fx`; an undated lot or a missing rate uses today's and is marked approximate), gains, losses, net and the part held over a year (`LONG_DAYS`); dividends as entered (what the broker paid, after tax withheld at source) by country of listing, with the usual source rate only where it's well established (`WITHHOLDING`; European-listed funds get `FUND_NOTE`: their domicile decides). The Portfolio page's Tax year card; arithmetic, not advice (`CAVEATS`). Hand-checked in `test_tax_year_is_hand_calculated`. |
| `orders.py` | Orders prepared, you approve. `plan()` (`POST /api/orders/plan`: `new_money`, `sell`, `fractional`; nothing saved) drafts orders from the asset class targets by the Rebalancing card's rules: new money to the classes below target in proportion to how far below (the simulation's monthly rule); selling only when asked, bringing every class to target once one has drifted over `BAND` (2 points; inside it nothing is sold, with or without new money); sales first, then buys capped at the new money plus what the rounded-down sales raise (a class with nothing held is left out of the cap); approved orders not yet done count as if filled (`_pending`), so preparing again doesn't repeat them; within a class, by the value of what's already held there (a class with nothing held is listed in `empty` and gets an order only for the ticker you type for it, `picks`, refused unless it's of that class; never filled with a guess); whole shares rounded down unless fractions are allowed (crypto always fractional); under `MIN_ORDER` dropped; limit = latest close; a sale shows its first-in-first-out gain in the quote currency, after the lots open approved sales will take. Withheld while a holding has no data. `approve()` (`POST /api/orders`) saves the ticked ones as `approved` in the `orders` table, refusing a sale beyond what's held counting open approved sales; `GET /api/orders` lists open ones with today's price (flagged past `MOVED`, 3%) and the latest closed; `GET /api/orders.csv` is the ticket list for the broker. `mark_done()` (`POST /api/orders/{id}/done`: shares, price, date, fee) claims the order with one conditional UPDATE (`db.x_count`; a double click records it once, a ledger refusal reopens it), refuses a fill dated before approval, restates the order for a split since approval (`split_since`; the list and CSV too), and records it through `ledger.add` with the fee folded into the price (a fee in pounds for a pence-quoted stock is converted); `cancel()`. Quantities and prices are written in full (`exact()`, never `:g`); CSV text that a spreadsheet would run as a formula is prefixed with `'`. Backup orders rows are checked by `check_rows()` before restoring. The digest reminds of approved orders not marked done; Ask's portfolio tool lists them. There's no broker connection. Checked in `test_orders_prepared_approved_and_done`, `test_orders_after_review` (an independent review's findings) and `test_orders_ticker_for_an_empty_class`. |
| `backtest.py` | buy_hold, sma_cross, rsi_reversion, momentum and dca. Positions are shifted one bar to avoid look-ahead; costs are in basis points. |
| `scorecheck.py` | The score research, as designed in `docs/score-research.md` (rounds 1 and 2, each pre-registered and committed before data; every later change listed there with its reason; read it before changing the method). Round 2: every stock in the list (all regions, whatever Settings follows), ten years of prices (`data.long_closes`) and four annual statements (`data.statements`, from 90 days after year end; 120 as a check). Each month-start, each stock is scored with today's `scoring.factor_breakdown` fed only what was public; past market value = statement shares x quoted close (`data.plain_closes`) where `_shares_fit`. Judged by rank IC against what followed (3 months; returns in USD, risk on swings), each outcome against its country's average that month (`_pairs`; countries under 3 scored stocks left out). `overlap_t`: variance scaled by h, Student's t with n//h - 1 df (`p_one_sided`); noise passes 'works' about 2%; `verdict` needs 12 months and 4 df. Three candidates (gross profitability, financials excluded; profitability-only quality; risk-adjusted momentum), decided on North America + Asia-Pacific after Holm over three (`holm`, a missing p as 1) and confirmed on Europe, Middle East & Africa, Latin America (works alone, gain p < 0.05, gain positive in every region with 12+ months: `countedRegions`). A run decides only if complete (`counts`; 95% of each region, nothing skipped); the first complete run is frozen in `data/research/score-round2.json` (`frozen()`), never redrawn; an incomplete one is cached 24 h as evidence (`scorecheck:r2b:`). Built in the background (`cached_or_start`, `PROGRESS`, `RETRY_AFTER`). Checked by `test_score_research_*`. Decision run Nov 2026 (407 stocks, Nov 2017-Oct 2026): risk works (calm), overall works (p 0.005), value suggestive, momentum suggestive within countries, growth no evidence, quality backwards (mostly Europe); nothing adopted. `GET /api/scorecheck`. |
| `simulate.py` | Portfolio-level simulations of a mix (weights must add up to 100%, at most `MAX_ASSETS`). `prices()` gives adjusted closes in the base currency at each day's rate, from the first day every asset has a price, and names the asset that sets the start; with stand-ins, a fund in `universe.STAND_INS` takes an older same-index fund's moves before its own history (scaled to meet it, named in the results). `backtest()` (`POST /api/simulate/backtest`) runs `_run()` day by day: new money on each month's first trading day goes first to what's below target, rebalancing (never/monthly/quarterly/yearly) on each period's first trading day, both at that close and paying the cost; the growth line is time-weighted (the first purchase's cost counts), with yearly returns (part-years marked, best/worst only of full years), the longest time below a high, and the money-weighted return when money is added; against the benchmark held the same way, left out when the mix is the benchmark. `monte_carlo()` (`POST /api/simulate/future`) draws futures from the mix's whole calendar months (`monthly_returns`) in 12-month blocks (`BLOCK_MONTHS`, wrapping round), so crashes keep their run; `expected` shifts every month's log return so the average is that yearly return while keeping history's swings; it needs `MIN_MONTHS` and says when history is under ten years; seed 1, so the same inputs give the same futures; bands are percentiles, in today's money with inflation. Checked against formulas and separate sums in the tests, and live against raw Yahoo (SPY in EUR: 176.85% both). `GET /api/simulate/mix` gives today's holdings as a mix. |
| `ai.py` | The optional model, through httpx. `config()` reads the provider from the environment on every call; `complete()` calls Anthropic's `/messages` or an OpenAI-style `{AI_BASE_URL}/chat/completions` (Ollama, LM Studio, OpenRouter, Groq), with a 180 s timeout for servers on this computer or network and 90 s otherwise, and strips `<think>` blocks and gpt-oss's own source marks ("【get_stock†L31-L33】"). `brief()` falls back to `rule_brief()` on any error or timeout. Accuracy comes first: `brief_data()` gives the model every figure already in its unit ("142.1%", "38.1x", "4.98T USD"), leaves missing ones out, explains the score scale (a high risk score means LOW risk) and keeps only headlines naming the company (`relevant_headlines()`); `BRIEF_RULES` forbids new figures and comparisons that aren't in the data; temperature is 0. `check_figures()` then matches every figure in the reply against that same text (same unit, allowing for rounding and a dropped minus sign) and the page shows how many matched and which didn't. `check_brief()` keeps the "What would change the view" section apart: levels a model suggests there are listed as its own, not as errors. Worked-out figures keep their parts' signs (12.3% and -4.5% are 16.8 apart; a sum only of parts on the same side of zero); "pp"/"percentage points" is a unit that matches a percentage or a gap between two; a figure described going the wrong way ("rose 6.15%" when the data has only -6.15%, by `_direction`'s words before or after it) is listed in `direction` and unmatched, and the rewrite is told which way the data goes; "12 m" is twelve months, not millions. Typographic hyphens and narrow spaces (gpt-oss writes "50‑day", "‑1.0 %") are read as plain ones. Screener requests: the keyword rules (`_rules()`) read typed numbers however written (`_typed_limits()` over `LIMITS`: "4 percent", "15x earnings", "at least 4% yield", "3% or more", "$50bn market cap", "rsi below 30", "down 30% from the high", "up 20% over the past year", "doubled this year"), a count isn't a limit ("top 10 dividend stocks"), and a limit pointing the way the screen can't filter ("yield under 2%") is reported, not flipped; then words with a stated meaning (`MEANINGS`, `_WORD_LIMITS`: cheap is P/E 18, large cap $10bn+, oversold RSI 30, near the high within 5%, beaten down 25%+ below it), then industries (`INDUSTRY_WORDS` to Yahoo's names in `universe.INDUSTRIES`, longest phrase first; several at once; a sector beside an industry outside it joins as its industries; exclusions take a list). `parse_query()` asks the model only when the rules left a word unread, at low reasoning effort (`complete(effort=)`), with `MEANINGS` and the industry names; a typed number stands over everything, a word's meaning over the model's own limit unless the model's is a number written in the request, and the model lists what no filter can express (`unread`), shown as not applied with what the rules set aside. `tests/screen_cases.py` measures it: the rules' requests offline in the smoke tests, all of them against the real model with `tests/check_screen_ai.py` (spends the allowance, not in `run_all.py`; 63 of 65 on gpt-oss-120b). "Banks" filters the bank industry, not all of Financial Services; a debt limit is set aside for banks with a note in the results. For banks, `brief_data()` leaves out free cash flow, debt/equity and the current ratio and says why, and the page hides the DCF and the FCF bars. It reads the first JSON object from the reply (fences and reasoning removed), checks every value with `_tidy_filters()`, asks once more if the reply is unusable, then falls back to the regex parser. `describe()` feeds the sidebar badge and never includes the key. |
| `agent.py` | Ask ClearYield. The page starts a question with `POST /api/ask/start` and checks `GET /api/ask/job/{id}` twice a second (left out of the request log): each look-up, thinking round, wait and check arrives as an event (`_say`), shown as it happens; `POST /api/ask` still answers in one call (tests). What a question plainly needs is looked up first, in parallel, with no model call (`prefetch`: the portfolio for "my"/"portfolio"/"should I", each stock it names by ticker or name (`mentioned`, at most `MENTIONS_MAX`; one-word names that are everyday words are in `NAME_STOP`), their news for "why"/"today"/moves, `compare` for two or more with "vs"/"or"/"compare", markets for market words) and handed over with the question, so the first call often answers; each round's tools also run in parallel (`run_tools`). Every round gets the configured reasoning and room to answer (tool rounds used to think "low" in 1,500 tokens, and answers written there contradicted themselves). Pacing is per key (`_pace`): each key's room is kept from its own `x-ratelimit-*` replies and refills at the minute's limit over 60 s (`_room`); the call goes to a key with room and waits only when every key is short (it used to sleep on one key while the others sat idle: 60 s on three questions in four). `_need` counts a call as its characters / 4.5 plus half its `max_tokens` (Groq counts part of the reply allowance up front, measured). Follow-ups: answers are kept in `RECENT` with their data; the page sends the ids (`follow`, at most `FOLLOW_MAX`), their questions and answers go first as the conversation, and their data counts for the figure check. The model answers a question by calling read-only tools in a loop (`TOOLS`: portfolio, watchlist, digest, stock, screen, opportunities, compare, pretrade, analysts, earnings, dividends, price history over any dates, fund contents, markets, search, news; analysts come from `data.analysts()`, dividends from `data.dividend_payments()`), at most `MAX_ROUNDS` (3) rounds plus one to answer, in OpenAI-style and Anthropic formats. Tools return compact summaries with figures in their units and say what they mean (core above target is the lower-risk side; look-through vs direct weights), since a model fills gaps with guesses. The answer's figures are checked against all tool results (`ai.check_figures`, which reads bn/k too, and lists as `derived` a figure that is simple arithmetic on the answer's own verified figures written near it, on the same line or within `NEAR` characters outside a table, with sums keeping the unit, shares and changes only of amounts, and a percentage only of an amount: `_worked_out`; among forty figures, two unrelated ones once multiplied to an invented fund cost). Quotations (20+ characters) are checked word for word against the same text (`ai.check_quotes`; a model rewrote a headline and kept the quotation marks). Figures still unsupported and misquotes go back to the model once in a fresh conversation (`_revise`), to correct from the data or remove; the revision is kept only if it has fewer (`revised`). The page marks what remains (`markFigures`: unsupported highlighted, worked-out underlined with how), in briefs too. The model is told today's date (it can't know it otherwise). Paced to the provider's per-minute token allowance from its `x-ratelimit-*` headers (Groq's free plan: 8,000 tokens a minute and 200,000 a day, rolling; an Ask uses 3,000-6,000), waiting up to `PACE_LIMIT` (60 s) for a minute's limit rather than failing, while a day's limit is reported at once with Groq's own wait (`_limit_message`); a malformed tool request is retried once, and if the model still asks for look-ups when it should answer, `_answer_from_findings` answers afresh from the question and what was found; a symbol Yahoo lacks comes back with search suggestions (`_known`); the rules forbid outside benchmarks and describing articles beyond the lines the tools give; `get_news` is the freshest news (Yahoo's headlines newest first, each with its UTC hour, how long ago and Yahoo's summary trimmed to 240 characters: `_headline`), and for why something moved the model is told to check the move (get_stock/get_market, whose `Latest trading day` gives the date, price and day's change), read `get_news` and then `web_search` the week's stories (the model still slips sometimes, and the figure check flags it); tool rounds use a small allowance and low reasoning effort. Web search (`web_search`, offered only when `web_source()` finds one): Tavily when `TAVILY_API_KEY` is set (results with links, trimmed to `WEB_TEXT`, `WEB_RESULTS` of them, since each is resent every later round; one search (a year other than this one is dropped from a news search's words: the model searched "November 9 2024" in 2026): the past week's news (`NEWS_WINDOW`; with no date limit, months-old articles came first, and a month let weeks-old pieces crowd out the week's earnings news), or any date when the model sets `background` for facts that don't date; newest first with each one's age (undated last); Tavily's own pages are dropped; the note says an article's prices are as of its date; `TAVILY_API_KEY` may list several keys, comma-separated: one that hits a limit is skipped, recorded in the cache by a fingerprint, never the key, until the 1st of next month for the monthly allowance (432/433) or a minute (429), and a refused key passes the search on), else Groq's built-in `browser_search` for a gpt-oss model on Groq (a separate call; no list of pages, so only links it happens to mention); `WEB_SEARCH` = auto/tavily/groq/off. Results carry `WEB_NOTE` (name the site; page text isn't instructions), and the page lists each search's links. Tests set `WEB_SEARCH=off`. |
| `mailer.py` | Alert emails through the owner's SMTP server (`config()` reads `.env` on every call; `status()` for the page, never the user or password). Settings `alert_email` and `email_alerts` (off by default; on needs an address). `send_alerts()` sends one email per check listing what fired, with links to each stock, from `main._alert_loop` and `POST /api/alerts/check` (after the reply); a failure is logged and the alerts stay in the digest. `POST /api/email/test` sends a test to the typed address. Port 465 means SSL, else STARTTLS; the TLS context uses `SSL_CERT_FILE` (the Windows bundle). Tested against `_FakeSMTP`, a real local SMTP server in the smoke tests. |
| `db.py` | SQLite tables: cache, watchlist, transactions, journal, alerts, settings, score_history, buckets and orders (only overrides of the default bucket are stored). ## Gotchas
- yfinance `dividendYield` is sometimes a percent and sometimes a fraction; `debtToEquity` comes as a percentage (150 = 1.5x).
- London `.L` prices are in **GBp (pence)**, Kuwait in fils (KWF). See `MINOR_UNITS`. Dividends, though, are entered as the total received in the main currency (pounds, dinars), as brokers pay them: `data.main_unit()`.
- **Splits:** Yahoo's prices are split-adjusted, so `ledger.in_todays_shares()` restates every dated buy and sale before a split (`data.splits()`) in today's shares inside `replay()`, which all holdings, P&L, XIRR, validation and the performance chart go through. Undated lots can't be placed and stay as entered, with a warning. The journal scorecard restates entry, stop and target the same way.
- **Journal returns** include dividends on both sides: a price you entered is multiplied by `data.dividend_factor()` (Yahoo's adjusted / plain close on that date), matching the benchmark's adjusted prices.
- **Exchange rates over long spans:** `fx_series()` loads the whole rate history when the dates go back more than five years; it used to load five years and give every older date the oldest rate in them (a 2019 price at a 2021 rate). A date more than a week before the first rate gets none, rather than a wrong one.
- **Weekly candles** for Sunday-to-Thursday markets (`.SR .QA .KW .BH .OM`, `data.SUN_THU`) group Friday to Thursday; the UAE has traded Monday to Friday since 2022.
- **RSI** of a price that doesn't move is 50, not 100. **Portfolio risk** (volatility, drawdown, Sharpe, beta) uses each day's FX rate, like the performance chart. The Core & satellite comparison runs over the whole history, with undated lots from the first dated trade.
- Gulf fundamentals on Yahoo are mostly there now (Nov 2026: P/E, P/B, margins and growth for all 32 Gulf stocks). The gaps were debt / equity, the current ratio and free cash flow, and 14 of those 16 stocks are banks, where they aren't scored. `insights.fill_from_statements()` works out what Yahoo leaves empty from the company's annual statements (`data.financials()`'s FCF, `data.balance()`'s debt, equity, current assets and liabilities; Yahoo's `totalDebt` of 0 means no debt), labelled with the year in the breakdown and the brief (`statementYears`); across all 407 stocks, 37 missing figures became 7, those 7 being companies with negative equity (ABBV, MCD, PM...), where debt / equity means nothing. Expect `None` otherwise, shown as "—". Abu Dhabi (ADX) isn't on Yahoo at all (no prices, not found by its search). Some Korean companies have no P/E or ROE.
- **Background scoring:** `main._warm_loop()` builds the sector table 20 s after start and every `WARM_EVERY` (6 h), so the day's first Screener, Opportunities or Research page doesn't wait about a minute (387 stocks cold: 69 s; warm: 6 s). Off in demo mode and when `CLEARYIELD_WARM=0` (the test servers).
- **SQL `LIKE` in tests:** `_` matches any character and case is ignored, so `'%gsk_%'` matched "GSK.L". Use `instr()` to look for exact text.
- The Gulf indexes `^TASI.SR` and `^GNRI.QA` return a single day of history, so the dashboard follows the KSA and QAT ETFs instead.
- European funds are listed only with an exchange suffix (VWCE doesn't exist on Yahoo, VWCE.DE does). Search adds Yahoo's results to the built-in list for this reason.
- **Inline event handlers:** an `onkeydown = (e) => cond && action()` handler returns `false` for other keys, which cancels them, so nothing can be typed. Use a block body.
- **Browser tests:** Playwright's `fill()` sets the value without key events. Use `pressSequentially()` when the point is that typing works.
- **Tests and AI:** `tests/test_smoke.py` and the servers started by `run_all.py` set `AI_PROVIDER=none`, so they never wait on the model in `.env`. `_FakeLLM` in the smoke tests is a real local HTTP server standing in for a provider.
- **Certificates on Windows:** Kaspersky on this machine (and company proxies elsewhere) re-signs HTTPS, which Python's own certificate list rejects. At startup `main._trust_windows_certificates()` writes certifi's list, the Windows root certificates trusted for server authentication (not code-signing-only ones), and the intermediates in Windows' CA store that chain up to those roots (`_chained_intermediates`; a network that inspects HTTPS through an intermediate, as one here does for Groq, fails without them) to `data/ca-bundle.pem` and sets `SSL_CERT_FILE`, which both yfinance's curl_cffi and httpx read, so `run.bat` reaches Yahoo and cloud AI providers. An `SSL_CERT_FILE` set beforehand is kept.
- **Cache:** `db.py` keeps a copy in memory of each cache row (as its JSON text, decoded afresh on every read), so a portfolio view doesn't open SQLite for every history and rate. Change the cache only through `cache_set`/`cache_expire`/`cache_clear`/`cache_prune`, never with SQL, or the copy goes out of step. Clear cache makes the time negative (expired, age kept); at startup `cache_prune()` drops anything not refreshed for 90 days. An empty answer from Yahoo (search, fund holdings, financials, earnings) is kept for an hour, never over what was known, since a rate limit looks the same.
- **Displays say what they show:** `info()` adds `priceUnit` (`"%"` for yields like `^TNX`, `"points"` for indexes, else none) and the page formats prices with `priceOf()`, never `money()` alone. The day's change reads "Today" only when every holding's latest price is from today, else "Latest day" with the dates (`dayFrom`/`dayTo`). Estimated income is what each share actually paid over the past year (`data.dividends_past_year()`, so accumulating funds give 0), with Yahoo's yield only as a fallback. An old price (Yahoo not answering) is marked "old price" wherever it shows. A missing annual return gives its real reason (`xirrWhy`).
- **Security:** the app has no login, so the middleware answers only a localhost `Host` and refuses `/api/` requests another site made through the browser (`Sec-Fetch-Site` other than same-origin/none, or an `Origin` that isn't this host; scripts with neither pass). Anything that spends the AI allowance is a POST (the brief). Every setting goes through `db.check_settings()` on save and restore (a bad stored value falls back to the default), and anything stored is escaped with `esc()` before it goes into HTML.
- **Currency look-through:** the Portfolio's currency chart counts broad funds by the currencies of what they hold, from `universe.FUND_CURRENCIES` (rounded index country weights: all-world, developed world, US only; approximate, so update them when they drift); any other holding counts in its trading currency's main unit. The currency concentration warning uses the look-through. Yahoo doesn't publish a fund's currency or country split.
- **Advice that costs nothing comes first:** rebalancing offers the new-money route (`rebalanceNewMoney`, per class `newMoney`) before selling; core above its target is "Above core target" (the lower-risk side: nothing to sell, `newMoney` into satellite if wanted) and only satellite over its share ("To core") gets a digest line. The digest's "review the thesis" is for company shares only, and stance changes skip `CORE_FUNDS`. Under a year of history the annual return isn't annualised (GIPS); the page shows `returnSoFar`.
- **Opportunities rules:** ranked lists hold at most `SECTOR_CAP` (3) from one sector; the portfolio fit compares weekly returns over `FIT_PERIOD` (2y) with both the candidate and what you hold in the base currency; "Quality on sale" needs the fall paused (back above the 50-day average) and sorts by quality. The DCF's default growth is the 3-year revenue rate (0-15%), and the page leads with the growth the price implies and the range across the grid.
- **Beta:** Yahoo's beta was checked against one computed from prices (2y weekly vs ACWI, in USD): they agree where it matters (TTE.PA 0.04 is real: oil majors moved apart from the world market). It's kept.
- **Broad index funds** (`CORE_FUNDS`) don't trigger the single-position concentration warning, and holding one means no "only N positions" warning: a world fund is thousands of companies.
- DCF fair value converts statement currency to quote currency, but cross-listed stocks remain approximate.
